**Инфраструктура честного обмена для любых автономных участников — людей, сервисов, устройств и агентов.**

Простыми словами: ACP (Autonomous Contract Protocol) — способ для независимых сторон договариваться об обязательствах, доказывать их выполнение и рассчитываться — без посредника и без веры на слово. Один участник публикует машиночитаемый **контракт**, другой исполняет его в **песочнице** и прикладывает **доказательство**, бюджет лежит в **escrow** до проверки, а **хаб подписок** раздаёт события с честными отказами вместо молчаливой потери.

Всё общение — обычные **письма**: конверты в духе RFC-822 с JSON-телом. Никакой магии: письмо читается в любом редакторе, живёт в git и доставляется чем угодно.

Pactum — референс-реализация: Rust-workspace, один бинарник, продакшн-стек (tokio + axum + clap + serde).

## Почему универсальность

Протокол вырос из [acp-mvp](https://github.com/kostyk348/acp-mvp) — сети, где ИИ-агенты заключали контракты друг с другом. Концепция оказалась шире агентов. Одни и те же три вопроса определяют честный обмен для *любых* автономных сторон:

- как **договориться** — контрактом, а не сообщением в чате;
- как **доказать**, что сделано — перепроверяемым доказательством, а не «поверь мне»;
- как **разузнать** — подписками с честными отказами, а не молчаливым опросом.

Поэтому «агент» ушёл из названия. **ACP теперь Autonomous Contract Protocol**, а участник — всё, что может держать ключ и действовать: человек, крон-задача, микросервис, станок с ЧПУ, организация, агент.

## Три примитива

| Примитив | Родословная | Что это |
|---|---|---|
| **Контракт** | [acp-mvp](https://github.com/kostyk348/acp-mvp) | обязательство + правила проверки + escrow + репутация; жизненный цикл `Initiated → Accepted → Completed → Released / Refunded / Slashed` |
| **Поток (хаб)** | [hubd](https://github.com/kostyk348/hubd) | подписки на топики с арендой, персистентная очередь ретраев, честный отказ (`404` = «не хочу», `hub.mode=denied`), `413` на слишком большое тело — ничего не теряется молча |
| **Доказательство** | [proof](https://github.com/kostyk348/proof) | заявление + точная команда + отпечаток вывода; три вердикта (`подтверждено / устарело / сломано`); любой перепроверяет одной командой |

Плюс общий фундамент: **письма** (подписанные конверты RFC-822), **capability-релей** (fan-out по умениям, с wildcard) и **цепочка фактов** — память, связанная хешами: любая подделка её ломает.

```bash
# опубликовать контракт от лица заказчика
pactum contract new --capability ci.compile.rust --title "Собрать wasm" \

    --budget 1.00 --unit USDC --out contract.json

# исполнитель обрабатывает входящие (accept → песочница → письмо-доказательство)

# заказчик проверяет доказательство и высвобождает escrow
curl -s -X POST http://127.0.0.1:9002/process
```

## Как проходит сделка

```
        УЧАСТНИКИ (человек / сервис / устройство / агент)

┌───────────────┐   письмо-контракт  ┌──────────────────┐  fan-out   ┌──────────────────┐
│  Заказчик     │ ─────────────────▶ │  РЕЛЕЙ           │ ─────────▶ │  Исполнитель     │
│  (Principal)  │                    │  по capability:  │            │  (любой природы) │
│               │                    │  кто умеет X?    │            │                  │
│ 1. публикует  │                    └──────────────────┘            │ 1. принимает     │
│ 2. заморажи-  │                                                    │ 2. исполняет в   │
│    вает бюд-  │              ┌──────────────────────┐              │    песочнице     │
│    жет в      │  письмо-proof │  ESCROW (sim или    │              │ 3. прикладывает  │
│    escrow     │ ◀──────────── │  AgentEscrow.sol)   │              │    proof         │
│ 4. проверяет  │               │  - держит бюджет    │              └──────────────────┘
│ 5. высвобож-  │               │  - release / slash   │
│    дает       │               └──────────────────────┘

Репутация живёт вместе с расчётами: успех +1, провал −1, тишина после дедлайна −5.
```

- бюджет нельзя вывести до доказательства — его не может тронуть никто;
- ставка исполнителя сгорает, если он молчит после дедлайна;
- факты о сделке пишутся в hash chain на обоих узлах.

## Кто такой участник

| Участник | Как заказчик | Как исполнитель | Как подписчик |
|---|---|---|---|
| Человек / команда | заказывает задачу, проверяет proofs | делает работу, доказывает | получает уведомления в слушатель |
| Сервис / крон | заказывает деплои и бэкапы | выполняет, доказывает через `proof` | следит за топиками инцидентов |
| Устройство / IoT | — | отчитывается данными как событиями | получает обновления конфигурации |
| ИИ-агент | заказывает подзадачи | исполняет в своей песочнице | мониторит спрос на свои умения |

CLI сделан для людей, REST API (`/inbox`, `/outbox`, `/process`, `/hub/*`, `/relay/*`) — для программ. Протокол и письма одни и те же.

## Расчёты и Solidity-референс

Расчёты — это трейт (`SettlementProvider`), а не вероисповедание:

- **`sim`** — встроенный детерминированный escrow-движок: полный жизненный цикл, делёж royalty, слэшинг, репутация; работает локально, без блокчейна;
- **блокчейн** — [`contracts/hardhat/contracts/AgentEscrow.sol`](contracts/README.md) из acp-mvp — референс-бэкенд (ERC-20 + нативный эфир, `slashOnTimeout`, репутация в сети) с 10 hardhat-тестами. web3-адаптер — в дорожной карте; трейт уже стабилен.

### Деньги опциональны

Ничему из перечисленного не нужны платёжные рельсы. Escrow-движок хранит бюджет непрозрачной строкой — `"0"` валиден, и жизненный цикл (заморожено → выплачено / возвращено) ведёт себя точно так же, — так что сдерживателем остаётся репутация (+1 / −1 / −5). Хаб, сканер, доказательства и цепочки фактов вообще не касаются расчётов: каждый — самостоятельный крейт (см. [Крейты](#крейты)). Типовые сценарии без денег:

- браузерная [консоль-демо](https://kostyk348.github.io/pactum/console/) — подписка → контракт → сбор → доставка → proof → release целиком на нулевом бюджете (и можно подмешать 413, честный 404 или подделанный факт — и увидеть, как отвечает репутация);
- сервисы обмениваются подписанными событиями через хаб (`pactum hub serve`) — с ретраями и честными отказами вместо молчаливых потерь;
- заявления проверяются в CI через `pactum proof` — вердикты verified / moved / broken, тайм-аут команды 120 с;
- аудиторские следы хранятся как цепочки фактов и проверяются `GET /facts/verify`;
- контракты с нулевым бюджетом, где единственная валюта — репутация.

«Без денег» теперь буквально: `cargo build --no-default-features -p pactum-cli` собирает бинарник с id, хабом, сканером, proof, фактами и witness — без escrow и узлов.

## Witness: нотариус контента

**Pactum Witness** (крейт [`pactum-witness`](crates/pactum-witness), группа команд `pactum witness`) — первое полноценное приложение на примитивах протокола, и деньги ему не нужны вовсе. Задача: *доказать, что документ — файл, страница, релизный артефакт — в момент T существовал ровно в таком виде*. Скриншоты подделываются, сторонние архивы централизованы и неаудируемы; приёмник Witness — подписанное заявление (ECDSA P-256), которое любой проверит офлайн хоть через годы:

```bash
pactum witness notarize dogovor.pdf --store           # → подписанный приёмник: seq, SHA-256, время
pactum witness verify receipt.json --dir witness-data # офлайн: подпись + принадлежность журналу
pactum witness serve --listen 0.0.0.0:8090            # REST-нотариус: POST /notarize, /notarize/url
```

В каждом приёмнике лежит открытый ключ нотариуса — проверка не требует ни сервера, ни сети. Журнал (`receipts.jsonl`) — append-only хеш-цепочка: переписать историю нельзя, а повреждённый журнал сервис честно не поднимает. Подписанные checkpoint-ы публикуются в хаб (топик `witness.head`) — третьи стороны со-свидетельствуют состояние. Отказы честные: `413` слишком большое, `429` слишком часто, `404` не нотариован, `502` источник недоступен. Полное руководство: [`docs/WITNESS.md`](docs/WITNESS.md) · страница: [kostyk348.github.io/pactum/witness](https://kostyk348.github.io/pactum/witness/).

## Безопасность

| Угроза | Митигация |
|---|---|
| Фальшивый proof | exec_hash = SHA256(stdout+stderr), коды возврата, проверка артефактов, автоverify по правилам |
| Исполнитель пропал | дедлайн + `slashOnTimeout` + репутация −5 |
| Кража бюджета | деньги в escrow до proof; высвобождение только по правилам контракта |
| Спам | минимальный бюджет, подписки по capability, репутация |
| Подделка истории | hash chain на каждом узле |
| Поддельные письма | ECDSA P-256 над каноническими байтами; keystore AES-256-GCM + PBKDF2 (200k) |

## Честные ограничения

- **Песочница ≠ TEE.** В v1.0 проверки исполняются локально с тайм-аутами; для враждебного кода подключите docker/TEE-бэкенд в трейт `Sandbox` (шов готов).
- **TLS в самом релее нет** — ставьте за TLS или в доверенной сети.
- **SMTP-транспорт в дорожной карте** — письма уже имеют форму конвертов; встроены HTTP-релей и файловый спул.
- **Хаб — один процесс** — его состояние в JSON-файле; кластеризация — пункт дорожной карты.

## Дорожная карта

1. web3-адаптер к `AgentEscrow.sol` (сначала Sepolia);
2. TLS для релея и писем узел-узел;
3. SMTP-транспорт (письма уже конверты);
4. docker/TEE-бэкенды песочницы;
5. discovery узлов (DNS-реестр / DHT вместо ручных подписок);
6. двусторонняя ставка (заказчик тоже кладёт депозит против «заказал и пропал»);
7. кластеризация и репликация хаба.

## Родословная и ребрендинг

Pactum объединяет три репозитория одного автора, переименованные и обобщённые с «только агентов» до любых автономных участников:

| Было | Стало |
|---|---|
| [acp-mvp](https://github.com/kostyk348/acp-mvp) — Agent Contract Protocol (Python + Solidity) | примитив **Контракт**: `pactum-contract`, `pactum-node`, `contracts/` (Rust + тот же Solidity-референс) |
| [hubd](https://github.com/kostyk348/hubd) — хаб подписок и сканер (Python) | примитив **Поток**: `pactum-hub`, `pactum-scan` |
| [proof](https://github.com/kostyk348/proof) — заявления с доказательствами (Rust) | примитив **Доказательство**: `pactum-proof` (плюс тайм-ауты команд) |
| память `sint_ua` | цепочка фактов в `pactum-core` (`pactum facts`) |

Что сохранилось: философия честного отказа, экономика escrow (+1/−1/−5 репутации), плоский реестр доказательств, WebSub-совместимая семантика хаба, идентичность на ECDSA P-256, идея письма-конверта. Что изменилось: один язык (Rust), один бинарник, одна спецификация протокола (`acp/1`) и участники, которым больше не обязательно быть агентами.

## FAQ

**Зачем письма (RFC-822), а не просто JSON по HTTP?**
Конверт не зависит от транспорта и читается человеком. HTTP-релей, файловый спул и будущий SMTP несут одни и те же байты; git бесплатно даёт diff и ревью.

**Кто гарантирует, что исполнитель не соврёт?**
Никто на слово. Деньги в escrow, доказательство несёт хеши и коды возврата, правила проверки — в контракте. Не сошлось — рефанд; тишина — слэшинг.

**Может ли заказчик забрать деньги после того, как работа сделана?**
Нет. После `submitResult` выходы только по правилам: release, refund или slash.

**Это правда интернет-масштаб или локальная игрушка?**
Архитектура глобальная с первого дня: публичный релей + узлы по HTTP(S). Демо работает в одном процессе ради воспроизводимости. TLS и discovery — пункты 2 и 5 дорожной карты.

**Почему не только агенты?**
Потому что вопрос «кто исполняет контракт» никогда не был главным. Главный — «кто держит обязательство и кто его доказывает», а это люди и сервисы не меньше, чем агенты.
